一、v2 失败原因复盘
----------------
v2 只是把现有专题文档重排进"章"：第二篇 6-12 章是七个并列的
"机制专题"（helper 章、map 章、类型章……），每章上来就是机制
穷举（如第6章开篇"编号函数表"）——这是 API reference 的目录学，
不是书。书 vs 手册的本质区别：
  手册：按"系统组件"组织，穷举机制，读者带着问题来查；
  书：按"读者的学习旅程"组织，问题驱动、由浅入深，机制在
      "需要它的时刻"被引入（just-in-time），表格退到附录。
v3 组织原则：
  1) 每章 = 一段旅程：动机(要解决什么) → 历史(怎么来的) →
     动手做 → 讲原理(技术点此时引入) → 坑 → 深入一步 → 小结练习；
  2) 旧的六段模板保留，但降级为"章内引入新概念时的写法"，
     不再充当章节骨架；
  3) 三个入门项目不再独立成章，编织进第2/4/6/7/8/10/11章的
     "动手"小节；ruport 解析仍独立（终章项目）；
  4) 所有速查表/参数表/矩阵 → 附录。

三、与 v2 的本质差异
----------------
1. 第二篇从"7 个机制专题章"变为"任务链"：数据需求引出 map
   （4-6章）、网络重走引出 XDP/TC（7-9章）、观测引出探针
   （10-11章）——机制跟着需求走；
2. "helper/验证器/BTF/link"不再是独立章：验证器在第3章
   （被拒后学）、helper 在 2/7/8 章"要用时"引入、link 在 14.4、
   BTF 在 12 章以"分发困境"引入；
3. 三个入门项目编织进各章"动手"节；ruport 是全书收束项目；
4. 全部表格化内容退附录；
5. 每章统一收尾"小结与练习"，形成教材式节奏。
