# 序言

## 0.1 为什么写这本书

如果你想回答下面任何一个问题，最终都会走到 eBPF 面前：

- 这台机器上，**哪个进程**在吃掉带宽？谁在反复读那个敏感文件？
- 能不能在包进入协议栈之前就把它丢掉，而不是等 iptables 在半路拦截？
- 能不能观测任意一个内核函数的每次调用、参数和返回值——不用改内核、不用装模块、不用重启？
- 能不能给线上内核行为"打个补丁"，比如临时改一条转发规则、插入一段审计逻辑？

传统工具在这些需求面前各有各的死角：iptables 看得到包看不到进程；
/proc 看得到结果看不到过程；改内核太重，内核模块太险。eBPF 用一套
前所未有的思路回答了全部问题：**允许你把一小段代码送进内核执行，
但前提是内核能在加载前"证明"这段代码绝对安全**。

这套"验证 + 受限执行"的机制，把内核从"不可编程的黑盒"变成了
"可安全扩展的平台"。过去十年，它从包过滤器长成了覆盖网络、观测、
安全三大领域的庞大体系（Cilium、Falco、bpftrace 都构建其上）——
也正因为体系庞大，初学者面对的资料常常是零散的：要么是内核文档的
机制罗列，要么是工具手册的参数堆叠，缺一条"从零到精通"的完整路径。

本书试图补上这条路。它有两个鲜明的取向：

1. **按学习旅程组织，而不是按组件组织。** 你会先跑起来第一个程序
   （第 2 章），因为程序被拒才去学验证器（第 3 章），因为数据出不来
   才去学 map（第 4 章），因为要处理包才走进网络栈（第 7-8 章），
   最后才沉到内核源码与工程化（第五篇）。每个机制都出现在
   "你需要它的那一刻"，而不是开头一次性穷举。
2. **一切原理配图。** 验证器的状态推演、map 的内存布局、包在内核
   中的旅程……凡是流程与结构，都配 ASCII 图逐层拆解，拒绝"一句话
   带过"。

本书的实战底盘是 `ruport-go`（本仓库）——一个基于 cilium/ebpf 的
端口复用系统。它是全书的"毕业设计"：第 16-17 章逐模块精读时，
你之前学过的每一块拼图都会归位。

## 0.2 本书怎么读

全书六篇，依赖关系如下：

```
 第一篇 走进 eBPF ──── 认知 + 第一个程序 + 验证器
        │
 第二篇 数据之道 ───── map：让数据在内核与用户态之间流动
        │
 第三篇 网络即战场 ─── XDP / TC / cgroup：重走网络栈
        │
 第四篇 观测的艺术 ─── tracepoint / kprobe / fentry：换视角用 eBPF
        │
 第五篇 精通之路 ───── BTF/CO-RE、map 内核实现、Go 工程化、调试
        │
 第六篇 实战 ──────── ruport-go：从架构设计到逐模块精读
```

三条推荐读法：

- **初学线（从入门到精通）**：顺序通读，每章的"动手"小节必须亲手
  跑，"练习"必须做——这是把书读成能力的唯一路径；
- **工程线（已在用 cilium/ebpf）**：第 2 章快速过 → 第 4-8 章 →
  第 14-15 章 → 第 17 章；
- **进阶线（已会使用，想懂内部）**：第 3 章 → 第 12-13 章 →
  第 15 章 → 附录。

每章的固定节奏：**动机（要解决什么）→ 历史（怎么来的）→ 动手做 →
原理拆解（配图）→ 常见坑 → 小结与练习**。附录承担全部速查职责
（类型表/helper 表/bpftool 命令/版本矩阵/报错字典），正文不堆表格。

## 0.3 环境准备

建议环境（与本书所有示例验证口径一致）：

```bash
# Ubuntu 22.04/24.04（内核 5.15+/6.8，自带 BTF）
sudo apt install -y clang llvm libbpf-dev make golang-go
# 内核工具
sudo apt install -y linux-tools-common linux-tools-$(uname -r)   # bpftool
# 确认 BTF 存在（CO-RE 与 fentry 系列的前提）
ls -l /sys/kernel/btf/vmlinux
```

- **权限**：书中所有操作默认 root（或 `CAP_BPF/CAP_NET_ADMIN`）；
- **Go 库**：本书使用 cilium/ebpf **v0.22.0**（本仓库 `go.mod` 锁定，
  所有 API 签名写作时已逐一对照该版本源码核实）；
- **本书代码**：即本仓库。第 2 章起的动手示例可先在仓库内建
  `playground/` 目录跟随练习；`make` 一次即可体会完整构建
  （bpf2go 流程详见第 14 章）。

一个提前打好的预防针：**eBPF 的学习曲线前陡后平**。第 3 章的
验证器报错会让每个新手怀疑人生——这是必经之路，本书刻意把"被拒"
设计成第 3 章的主题：读懂拒绝信，你就跨过了 eBPF 最大的门槛。

## 0.4 约定

1. **版本口径**：全书"内核 X.Y+"指该特性合入 Linux **主线**的版本；
   发行版 backport 常使老版本号内核拥有新特性，判断以
   `bpftool feature probe` 实测为准（第 15 章、附录 E）；
2. **术语**：BPF/eBPF 在本书语境下同义（现代资料里 eBPF 是唯一
   存活的那个）；"map"指 eBPF 的键值存储；"钩子（hook）"指内核
   预留的程序触发点；
3. **图例**：正文所有图均为 ASCII 图，`★` 标注可挂钩子的位置、
   `→` 表示数据流向、`┌┐│└┘` 围出结构框；
4. **代码**：C 侧遵循内核samples/libbpf 风格（SEC/BTF map 定义），
   Go 侧即本仓库风格；示例默认可编译运行，不可运行处会明确标注。

准备好了吗？从第 1 章的一个真实烦恼开始。
